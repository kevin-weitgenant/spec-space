Rampa para iniciante (pode pular). spec-space é um servidor de documentação para pastas de arquivos HTML que você já tem. Você joga HTML na pasta e ele monta um site navegável, com sidebar em árvore, recarregamento ao salvar e até edição direto na página. Quando quer publicar, um comando congela tudo num site estático (dist/) — sem servidor, sem banco, sem build.

1📖 Sidebar & navegação

Como a árvore de docs nasce das suas pastas e como você se move por ela.

💡 HTML puro, sempre
Tudo abaixo funciona sobre HTML puro — sem build, sem dependências, sem transformar seus arquivos. No file:// ou num host estático o doc continua renderizando; os extras entram por injeção do dev server (ou ficam escritos no dist/ do export).
🌳Sidebar em árvore— nasce das pastas; nomes viram títulos

Pastas viram ramos colapsáveis, arquivos .html viram links. Jogue HTML na pasta e ele aparece. Nomes viram títulos (auth-service.html → “Auth Service”), com acentuação respeitada.

Como: src/domain/manifest.js varre a pasta e monta a árvore; nav.js renderiza.

📌Memória de colapso + doc ativo— estado lembrado entre visitas

Pastas colapsadas continuam colapsadas entre visitas (localStorage); o doc aberto fica destacado e suas pastas ancestrais se expandem sozinhas.

Como: nav.js guarda o estado por caminho e escuta o load do iframe.

🔗URL sempre sincronizada— deep links e botão voltar funcionam

A barra de endereço mostra sempre o doc corrente. F5 num link profundo (/pasta/doc.html) reabre o shell com a sidebar aberta naquele doc; voltar/avançar do browser funcionam.

Como: pushState/popstate no nav.js; deep link top-level recebe o shell via header Sec-Fetch-Dest (src/server/roots.js).

⋯Menu kebab por item— copiar caminho, revelar, mover, excluir

Cada doc e pasta da sidebar ganha um botão ⋯ (visível no hover) com menu suspenso: Copy path, Copy full path (absoluto, com o separador certo do SO), Reveal in Explorer/Finder/Files, Move to… e Delete — com confirmação em dois cliques dentro do próprio menu (“Delete for sure?”), sem confirm().

Como: makeKebab()/showMenu() no nav.js; caminho absoluto montado a partir de root/sep/platform que vêm no /__manifest__.

🖱️Menu de contexto da sidebar— nova pasta inline + colapsar tudo

Clique com o botão direito na sidebar abre um menu com New folder (criação inline, com input no próprio lugar) e Collapse all.

Como: contextmenu no <aside> + createFolder()/collapseAll() no nav.js (desligado no export).

🏷️Título da aba sincronizado— “Doc · Site”, sempre atual

A aba do browser mostra Nome do Doc · Título do Site — o título do site sozinho quando nada está aberto. Duplicar/nomear tabs fica útil de verdade.

Como: SITE_TITLE do /__manifest__ + document.title atualizado a cada troca de doc no nav.js.

🎬Três animações de colapso— guide, slide ou reveal

Escolha no _config.json: guide (linha-guia que desce — padrão), slide (desliza e some) ou reveal. Mudou o JSON, muda na hora (hot reload).

Como: sidebarAnim no _config.json → classe dl-anim-* no aside.

🎭Título e favicon editáveis— emoji vira ícone na hora

O título do shell aparece na aba e no cabeçalho; favicon pode ser um emoji (vira ícone SVG na hora). Duplo clique no título do cabeçalho renomeia e salva no _config.json.

Como: title/favicon no _config.json, aplicados por applyShellConfig(); renomeia via POST /__title__.

🎨Ícones Lucide embutidos + emoji— sem React, sem rede

Ícones da UI são paths Lucide embutidos no script; ícones personalizados de pasta aceitam um nome do set ou qualquer emoji.

Como: objeto ICONS no nav.js; valor não-ASCII renderiza como emoji (.dl-emoji).

↔️Esconder a sidebar— leitura em tela cheia, estado lembrado

Botão alinhado à esquerda do cabeçalho recolhe a sidebar para leitura em tela cheia — e o estado é lembrado.

Como: botão injetado pelo nav.js (ícone sidebar-left.svg).

2🔄 Live reload

Salvou, o doc certo recarrega sozinho — sem perder scroll nem estado.

⚡Salvou, recarregou — só a página certa— a sidebar nunca se mata por mudanças alheias

Editar um doc recarrega apenas ele no iframe. O shell nunca se mata por mudanças alheias: scroll, colapso e doc ativo da sidebar sobrevivem a qualquer edição. Mudança em .js/.css compartilhado recarrega o doc em exibição.

Como: watcher com debounce de 150 ms (src/server/reload.js servidor) → SSE → client/reload.js decide com shouldReload().

🗳️N tabs abertas, uma conexão só— eleição via Web Locks + BroadcastChannel

Abra quantas tabs quiser: só uma mantém a conexão SSE (eleita via Web Locks), re-transmitindo por BroadcastChannel. O limite de ~6 conexões por origem do browser nunca trava sua 7ª tab; se a líder fecha, o lock migra sozinho.

Como: leader election no client/reload.js; no manager o SSE já vem multiplexado com todos os roots (mensagens {base, path}).

🔥Hot reload da configuração— _config.json pega na hora

Mudou título, favicon, ordem ou ícones no _config.json? A UI pega na hora — sem restart do servidor.

Como: config lida a cada request (src/server/roots.js → src/domain/config.js); o watcher dispara o mesmo fluxo de reload.

3🔔 Mudanças desde sua última visita

Dots, chips e diffs palavra a palavra — desde a sua última visita, não desde o último restart.

🟢Dot verde na sidebar— mudou? você vê antes de abrir

Docs que mudaram desde a última vez que você as viu ganham um ponto verde na sidebar — visível antes mesmo de abrir o doc.

Como: mtime no manifest + evento docs-in-html:change → classe dl-changed no nav.js.

✨Chips “novo” + word-diff— edição mostrada palavra a palavra, no fluxo

Blocos novos ganham fundo verde e um chip “novo”; blocos editados mostram um diff palavra a palavra — o texto antigo riscado, o novo destacado — direto no fluxo da página, sem modal.

Como: changes.js achata os blocos do doc e faz diff LCS contra o snapshot da última visita — o núcleo é o módulo puro client/diff.js (UMD, window.DIFF), testável com node --test.

🗺️Minimap + pílula de navegação— estilo VS Code; clique na barra e pule

Enquanto houver mudanças não vistas, aparece um minimapa à direita com marcadores das regiões alteradas — clique numa barra para pular. Pílula fixa: “N mudanças · ↓ próxima · ✓ já vi tudo”.

Como: changes.js (marcações só enquanto há unseen changes).

🔵Sinal na aba do browser— favicon com ponto azul + “● ” no título

O favicon da tab ganha um ponto azul e o título um prefixo “● ” quando o doc aberto tem novidades — você vê de longe, com a tab ao fundo.

Como: changes.js troca o favicon dinamicamente (sinais vão ao window.top, same-origin sob serve e manager).

🌙Funciona até se você não estava olhando— o baseline é a sua última visita

O baseline é a sua última visita, guardada em localStorage — não o estado do servidor. Mudou com nenhuma tab aberta? Servidor reiniciado? O diff aparece do mesmo jeito na próxima visita.

Como: snapshot por doc em localStorage (changes.js).

4✏️ Edição inline

WYSIWYG na página renderizada: clique, digite, salve no arquivo.

✏️WYSIWYG sem ver uma tag— Ctrl+E edita · Ctrl+S salva

Botão “✏ Editar” no canto superior direito (ou Ctrl+E) torna a página renderizada editável: clique no texto, digite, Ctrl+S salva direto no arquivo. pre/code editam como texto puro. Sair do modo com mudanças não salvas pede confirmação (e o beforeunload protege contra fechamento acidental).

Como: edit.js liga contenteditable e grava via POST /__save__ (até 10 MB); toda a UI do dev server (marcada data-injected) é removida do clone antes de salvar.

🔴Indicador de “dirty”— o botão fica vermelho com mudanças não salvas

O próprio botão Editar fica vermelho quando há mudanças não salvas — impossível perder edição por engano.

Como: classe dirty no botão (edit.js).

5🗂️ Organização de arquivos

Reordenar, renomear, mover, criar e excluir — tudo pela sidebar, tudo persistido.

🥇Reordenar com drag & drop— pinneados primeiro, resto alfabético

Arraste docs na sidebar para fixar a ordem que quiser — pinneados ficam primeiro, na ordem que você definiu; o resto segue alfabético. Pastas são arrastáveis também. Persiste entre sessões, com ordem por pasta.

Como: drag no nav.js → POST /__order__ com {folder, order} → seção order do _config.json (lida pelo src/domain/manifest.js).

⇄Renomear e mover— inline com validação · popover de destino

Rename inline (com validação ao vivo do nome) ou “⇄ Move to…” com popover das pastas destino. Mover por drag & drop também funciona. A configuração acompanha: se o doc aberto foi movido, iframe e barra de endereço se atualizam sem 404.

Como: POST /__rename__ — o servidor reescreve as chaves de icons afetadas (shiftIcons em src/server/roots.js).

➕Criar pastas e excluir— input inline · confirmação em dois cliques

Crie pastas novas direto da sidebar (menu de contexto ou kebab de pasta — input inline no próprio lugar; pastas vazias ficam visíveis esperando docs). Excluir doc ou pasta vazia pede confirmação em dois cliques — pastas não-vazias são recusadas (409), por design.

Como: POST /__mkdir__ e POST /__delete__ (com rmdir que se recusa a apagar conteúdo).

📂Revelar no gerenciador de arquivos— Explorer/Finder/Files, já selecionando

Ação de contexto para abrir o Explorer/Finder/Files já selecionando o arquivo — o rótulo até muda conforme o SO.

Como: POST /__reveal__ → ops.openPath() (Explorer /select, Finder -R, xdg-open no pai).

6🔍 Diagramas

Mermaid e SVG ganham pan/zoom/lightbox automáticos, sem nenhuma tag extra.

🔍Pan/zoom/lightbox para Mermaid e SVGs— clique abre lightbox com zoom e tela cheia

Blocos Mermaid e SVGs avulsos ficam clicáveis — injeção automática, seu HTML não precisa de tag nenhuma. Conta como “avulso”: qualquer <svg> num <figure>, ou marcado .panzoom/.diagram/.zoomable. O clique abre um lightbox com arrastar, scroll para zoom, botões +/−/ajustar e tela cheia (funciona até dentro do iframe do shell — o nav.js garante allowFullscreen).

Como: mermaid-zoom.js injetado (defer) pela heurística do src/domain/inject.js; carrega svg-pan-zoom do CDN sob demanda.

🛡️Robusto a re-render e a elementos interativos— o zoom sobrevive; cliques úteis não são sequestrados

O Mermaid pode reescrever o DOM quantas vezes quiser — o zoom sobrevive. E um SVG dentro de button, a, [onclick], label ou summary nunca é sequestrado: o clique faz o que devia.

Como: listeners no document + pseudo-elemento ::after no contêiner; lista INTERACTIVE de ancestrais intocáveis.

7🛰️ Manager — todas as suas docs, um processo

Um processo na porta 4400 serve todas as docs registradas; servir uma pasta nova é o mesmo que registrá-la.

🌐Uma URL para tudo— localhost:4400/<slug>/ por pasta

spec-space manager serve cada pasta registrada em http://localhost:4400/<slug>/ — slug derivado do título da docs (“My Project — Handbook” → /my-project-handbook/), colisões resolvem com -2.

Como: src/server/manager.js + src/domain/registry.js; um contexto src/server/roots.js por pasta.

🤝Servir = registrar = delegar— CLI nem sobe servidor se o manager está no ar

Qualquer spec-space <dir> (npx incluso) registra a pasta no registry. Se o manager está no ar, o CLI nem sobe servidor — registra lá e imprime o link (com aviso se você passou --port, que é ignorado na delegação). --no-register desliga; --unregister remove.

Como: src/server/delegation.js (ping + /api/add) no startup do src/cli/serve.js.

🧱Mural de cards com pastas e ordenação— drag & drop, grupos, ordem persistida

A página inicial do manager é um mural: um card por docs (título + favicon), organizável em pastas/grupos com drag & drop — ordem e colapso persistidos no registry.

Como: client/manager.html + POST /api/layout (layout sempre saneado no servidor antes de gravar — escrita atômica).

⌨️Ações por card: Warp, reveal, remover— terminal, gerenciador de arquivos ou fora do registry

Abrir a pasta do projeto no terminal Warp (binário resolvido em $WARP_BIN → locais padrão → PATH, com cache por processo; no Windows o caminho vira URL file:// porque o Warp parseia argumento posicional como URI), revelar no gerenciador de arquivos, remover do registry.

Como: /api/open-warp (resolveWarp), /api/reveal, /api/remove — só agem sobre pastas registradas.

📡Importação por scan— acha todas as suas docs sob o home

O botão “Escanear” acha toda pasta com _config.json válido sob seu home (com skip-list e limite de profundidade) para registrar suas docs existentes em lote — as novas desde o último scan ficam destacadas.

Como: src/domain/scan.js via /api/scan; depois do import, o registry é a fonte da verdade.

8📤 Export & deploy

A experiência dev, congelada em arquivos estáticos — pronta para Surge, Netlify Drop ou GitHub Pages, e read-only por design.

📦Export congela tudo em arquivos— 5 passos: copiar → manifest → __docs__ → shell → injetar

spec-space export ./docs gera um dist/ pronto para surge dist, Netlify Drop ou GitHub Pages — sidebar, ordem, ícones, pan/zoom e deep links funcionam no site estático. Os passos: copia a pasta (pulando _config.json e os legados, sem copiar o output pra dentro de si) → gera manifest.json via buildTree → copia client/ → grava __docs__/ → garante o index.html (shell embutido com title/favicon) e reinjeta cada HTML com injectScripts(staticMode). Pasta inexistente → erro claro e exit 1.

Como: scripts já escritos nos HTMLs — nada depende de servidor no resultado.

🧭Deep link no host estático— bootstrap /?p= reabre o doc no shell

Alguém abre /guides/api.html direto no site publicado? Um pequeno script injetado no <head> detecta que é a janela top e pula para /?p=guides/api.html; o shell pega o parâmetro e abre o doc no iframe (âncora preservada).

Como: deepLinkBootstrap() no src/domain/inject.js + leitura de ?p= no nav.js (só no modo export).

🔒Read-only por design— sem endpoints, sem edição acidental

No site publicado, CRUD e edição ficam de fora (não há endpoints) — conteúdo público não é acidentalmente editável. Live reload e diff são dev-only, por design.

Como: nav.js/edit.js/changes.js desligam o que depende de servidor via window.DOCS_EXPORT.

9⚙️ Servidor & CLI

Os comandos disponíveis e como portas, registro e variáveis de ambiente se resolvem.

🔁 Renome suave
O pacote agora se chama spec-space. O pacote de alias docs-in-html mantém o CLI antigo funcionando: docs-in-html <dir> apenas faz require do src/cli/serve.js do spec-space. Nada quebra.
ComandoEfeito
spec-space [dir]Serve a pasta (padrão: dir atual), abre o browser, registra no manager. Auto-cria _config.json no primeiro serve.
spec-space managerServe todas as docs registradas em :4400 (ou $DOCS_MANAGER_PORT; --port explícito ganha dos dois).
spec-space init [dir]Scaffold de index.html + _config.json customizáveis (recusa sobrescrever).
spec-space export [dir] [--out]Congela para arquivos estáticos (saída padrão: ./dist).
-p, --port NPorta explícita — exigência: ocupada, morre com erro (sem --port, cai pra próxima livre com aviso, até 20 tentativas).
--no-open / --no-register / --unregisterNão abrir browser / não registrar / remover do registry e sair.
$PORT, $DOCS_MANAGER_PORT, $WARP_BINVariáveis de ambiente equivalentes.

11🎯 Quiz

Cinco perguntas sobre comportamentos reais — clique numa opção para responder na hora; pode trocar de resposta quando quiser.

1. Você sobe o servidor sem --port e a porta padrão está ocupada. E depois, com --port 3000 e a 3000 ocupada?

✅ C. Porta explícita é exigência: ocupada, o processo encerra com erro. Sem --port, o fallback procura a próxima livre com aviso, limitado a 20 tentativas.

2. Ao salvar uma edição inline via POST /__save__, para que serve a marcação data-injected na UI do dev server?

✅ B. O edit.js salva um clone da página; toda a UI dev marcada data-injected é removida antes da gravação, então o HTML puro no disco permanece limpo.

3. No site estático publicado, alguém abre /guides/api.html direto (fora do shell). O que acontece?

✅ A. É o bootstrap /?p=: deepLinkBootstrap() (injetado no head) redireciona para /?p=…, e o nav.js lê o parâmetro e abre o doc no iframe, com âncora preservada — só no modo export.

4. Com 7 tabs abertas no mesmo dev server, quantas mantêm a conexão SSE — e como as demais ficam sabendo das mudanças?

✅ B. A leader election por Web Locks garante uma única conexão SSE, evitando bater o limite de ~6 conexões por origem; se a líder fecha, o lock migra sozinho para outra tab.

5. Durante o spec-space export, a cópia da pasta pula quais arquivos?

✅ C. O primeiro passo do export.js copia a pasta pulando _config.json e os legados (e sem copiar o output pra dentro de si); a configuração entra no manifest.json gerado por buildTree.
