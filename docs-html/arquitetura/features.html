✨ docs-in-html — Features

Tudo o que o docs-in-html oferece, organizado pela jornada de uso. Cada card traz o o quê e, embaixo, o como (com link para a arquitetura do pacote quando você quiser descer ao código).

💡 Tudo abaixo funciona sobre HTML puro — sem build, sem dependências, sem transformar seus arquivos. No file:// ou num host estático o doc continua renderizando; os extras entram por injeção do dev server.

📖 Navegação

Sidebar em árvore, gerada das suas pastas

Pastas viram ramos colapsáveis, arquivos .html viram links. Nada de configurar navegação à mão — jogue HTML na pasta e ele aparece. Nomes viram títulos (auth-service.html → "Auth Service"), com acentuação respeitada ("Integração" não vira "IntegraçãO").

Como: manifest.js varre a pasta e monta a árvore; nav.js renderiza. → módulo Contexto por pasta

Memória de colapso + doc ativo destacado

Pastas colapsadas continuam colapsadas entre visitas (localStorage); o doc aberto fica destacado e suas pastas ancestrais se expandem sozinhas.

Como: nav.js guarda o estado por caminho e escuta o load do iframe.

URL sempre sincronizada — deep links e botão voltar

A barra de endereço mostra sempre o doc corrente. F5 num link profundo (/pasta/doc.html) reabre o shell com a sidebar aberta naquele doc; voltar/avançar do browser funcionam.

Como: pushState/popstate no nav.js; deep link top-level recebe o shell via header Sec-Fetch-Dest.

Três animações de colapso

Escolha no _config.json: guide (linha-guia que desce — padrão), slide (desliza e some) ou reveal.

Como: sidebarAnim no _config.json → classe dl-anim-* no aside. Mudou o JSON, muda na hora (hot reload).

Título e favicon da docs, editáveis

O título do shell aparece na aba e no cabeçalho; favicon pode ser um emoji (vira ícone SVG na hora). Duplo clique no título do cabeçalho renomeia e salva no _config.json.

Como: title/favicon no _config.json, aplicados por applyShellConfig(); renomeia via POST /__title__.

Esconder a sidebar

Botão alinhado à esquerda do cabeçalho recolhe a sidebar para leitura em tela cheia — e o estado é lembrado.

Como: botão injetado pelo nav.js (ícone sidebar-left.svg).

🔄 Live reload

Salvou, recarregou — só a página certa

Editar um doc recarrega apenas ele no iframe. O shell nunca se mata por mudanças alheias: scroll, colapso e doc ativo da sidebar sobrevivem a qualquer edição. Mudança em .js/.css compartilhado recarrega o doc em exibição.

Como: watcher com debounce de 150 ms (reload.js) → SSE → client/reload.js decide com shouldReload(). → fluxo Live reload

N tabs abertas, uma conexão só

Abra quantas tabs quiser: só uma mantém a conexão SSE (eleita via Web Locks), re-transmitindo por BroadcastChannel. O limite de ~6 conexões por origem do browser nunca trava sua 7ª tab.

Como: leader election no client/reload.js; no manager o SSE já vem multiplexado com todos os roots.

Hot reload da configuração

Mudou título, favicon, ordem ou ícones no _config.json? A UI pega na hora — sem restart do servidor.

Como: config lida a cada request (roots.js → config.js); o watcher dispara o mesmo fluxo de reload.

🔔 Mudanças desde sua última visita

Dot verde na sidebar

Docs que mudaram desde a última vez que você as viu ganham um ponto verde na sidebar — visível antes mesmo de abrir o doc.

Como: mtime no manifest + evento docs-in-html:change → classe dl-changed no nav.js.

Chips "novo" + word-diff nas linhas editadas

Blocos novos ganham fundo verde e um chip "novo"; blocos editados mostram um diff palavra a palavra — o texto antigo riscado, o novo destacado — direto no fluxo da página, sem modal.

Como: changes.js achata os blocos do doc e faz diff LCS contra o snapshot da última visita.

Minimap estilo VS Code + pílula de navegação

Enquanto houver mudanças não vistas, aparece um minimapa à direita com marcadores das regiões alteradas — clique numa barra para pular. Pílula fixa: "N mudanças · ↓ próxima · ✓ já vi tudo".

Como: changes.js (marcações só enquanto houver unseen changes).

Sinal na aba do browser

O favicon da tab ganha um ponto azul quando o doc aberto tem novidades — você vê de longe, com a tab ao fundo.

Como: changes.js troca o favicon dinamicamente (sinais vão ao window.top, same-origin).

Funciona até se você não estava olhando

O baseline é a sua última visita, guardada em localStorage — não o estado do servidor. Mudou com nenhuma tab aberta? Servidor reiniciado? O diff aparece do mesmo jeito na próxima visita.

Como: snapshot por doc em localStorage (changes.js).

✏️ Edição inline

WYSIWYG sem ver uma tag

Botão "✏ Editar" no canto superior direito (ou Ctrl+E) torna a página renderizada editável: clique no texto, digite, Ctrl+S salva direto no arquivo. pre/code editam como texto puro.

Como: edit.js liga contenteditable e grava via POST /__save__; tags/UI do dev server (marcadas data-injected) são removidas antes de salvar.

Indicador de "dirty"

O próprio botão Editar fica vermelho quando há mudanças não salvas — impossível perder edição por engano.

Como: classe dirty no botão (edit.js).

🗂️ Organização de arquivos

Reordenar arquivos (drag & drop)

Arraste docs na sidebar para fixar a ordem que quiser — pinneados ficam primeiro, na ordem que você definiu; o resto segue alfabético. Persiste entre sessões.

Como: drag no nav.js → POST /__order__ → seção order do _config.json (lida pelo manifest.js).

Reordenar pastas

Pastas também são arrastáveis — mesma mecânica, mesma persistência. Ícones personalizados por pasta também podem ser definidos no _config.json.

Como: mesma rota /__order__; ícones na seção icons.

Renomear e mover

Rename inline ou "⇄ Move to…" para trocar um doc de pasta. Mover por drag & drop também funciona. A configuração acompanha (ícones, ordem).

Como: POST /__rename__ — o servidor reescreve as chaves de icons afetadas (shiftIcons).

Criar pastas e excluir

Crie pastas novas direto da sidebar (pastas vazias ficam visíveis esperando docs). Excluir doc ou pasta vazia pede confirmação em dois cliques — pastas não-vazias são recusadas, por design.

Como: POST /__mkdir__ e POST /__delete__ (com rmdir que se recusa a apagar conteúdo).

Revelar no gerenciador de arquivos

Ação de contexto para abrir o Explorer/Finder já selecionando o arquivo.

Como: POST /__reveal__ (Explorer /select, Finder -R, xdg-open).

🔍 Diagramas

Pan/zoom/lightbox para Mermaid e SVGs

Blocos Mermaid e SVGs avulsos (qualquer <svg> num <figure>, ou marcado .panzoom/.diagram/.zoomable) ficam clicáveis: lightbox com arrastar, scroll para zoom, botões +/−/ajustar e tela cheia (funciona até dentro do iframe do shell). Injeção automática — seu HTML não precisa de tag nenhuma.

Como: mermaid-zoom.js injetado pela heurística do inject.js; carrega svg-pan-zoom do CDN sob demanda.

Robusto a re-render e a elementos interativos

O Mermaid pode reescrever o DOM quantas vezes quiser — o zoom sobrevive (event delegation + CSS). E um SVG dentro de button, a ou [onclick] nunca é sequestrado: o clique faz o que devia.

Como: listeners no document + pseudo-elemento ::after no contêiner; lista INTERACTIVE de ancestrais intocáveis.

🛰️ Manager — todas as suas docs, um processo

Uma URL para tudo

docs-in-html manager serve cada pasta registrada em http://localhost:4400/<slug>/ — slug derivado do título da docs ("My Project — Handbook" → /my-project-handbook/), colisões resolvem com -2.

Como: manager.js + registry.js; um contexto roots.js por pasta. → módulo Ecossistema multi-docs

Servir = registrar = delegar

Qualquer docs-in-html <dir> (npx incluso) registra a pasta no registry. Se o manager está no ar, o CLI nem sobe servidor — registra lá e imprime o link. --no-register desliga; --unregister remove.

Como: delegation.js (ping + /api/add) no startup do serve.js.

Mural de cards com pastas e ordenação

A página inicial do manager é um mural: um card por docs (título + favicon), organizável em pastas/grupos com drag & drop — ordem e colapso persistidos no registry.

Como: client/manager.html + POST /api/layout (layout sempre saneado no servidor).

Ações por card: Warp, reveal, remover

Abrir a pasta do projeto no terminal Warp (binário resolvido em $WARP_BIN → locais padrão → PATH), revelar no gerenciador de arquivos, remover do registry.

Como: /api/open-warp, /api/reveal, /api/remove — só agem sobre pastas registradas.

Importação por scan

O botão "Escanear" acha toda pasta com _config.json válido sob seu home (com skip-list e limite de profundidade) para registrar suas docs existentes em lote — as novas desde o último scan ficam destacadas.

Como: scan.js via /api/scan; depois do import, o registry é a fonte da verdade.

📤 Deploy estático

Export: a experiência dev, congelada em arquivos

docs-in-html export ./docs gera um dist/ com os scripts já escritos nos HTMLs, um manifest.json e __docs__/ — pronto para surge dist, Netlify Drop ou GitHub Pages. Sidebar, ordem, ícones e pan/zoom funcionam no site estático; deep links também (o doc aberto direto pula para o shell com a sidebar aberta nele).

Como: export.js + inject.js em modo estático (DOCS_EXPORT) + bootstrap de deep link. → módulo Publicação estática

Read-only por design

No site publicado, CRUD e edição ficam de fora (não há endpoints) — conteúdo público não é acidentalmente editável. Live reload e diff são dev-only, por design.

Como: nav.js/edit.js/changes.js desligam o que depende de servidor via window.DOCS_EXPORT.
